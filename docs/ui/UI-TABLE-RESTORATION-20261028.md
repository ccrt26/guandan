本轮依据用户提供的原始 ZIP；包内 17 个文件与 `deliverables/ui/reference-20261030/ui_play_tribute_handoff` 逐字节一致。采用该包的正常牌桌图和“继续”贡还图：我的手牌标签在牌行上方居中、正常页没有虚线占位框。牌面沿用既有 54 张 PNG，真实对局由引擎提供牌和座位。

## 根因与修改

旧实现把手牌左缘固定为 115、顶部固定为 586，同时把实际牌行宽度上限限制在 1570。容器变宽时，牌行没有随容器居中；高度变化时，也没有跟随桌底。因此 2551×1242 下实际牌行仍在约 x115–1685，牌底离底栏约 382px；1366×768 下牌底反而越过底栏顶约 93px。旧队友牌组使用居中的大容器、内部图片却左对齐，4 张牌的实际中心偏左约 83px。这些问题在 DPR=1、visual viewport scale=1 的浏览器里可以复现，不能归咎于用户“77% 缩放”。修复前证据保存在 `lab/out/layout-diagnosis-20261028`。

现在根据实际视口计算区域：1800×874 保留基准坐标，宽屏按设计比例增大组件，窄屏调整手牌步长和区域间距；手牌按实际张数居中、底部锚定，上下已出牌按实际组宽居中。选中抬升 18px 时标签避让，左右名牌与牌组留出间距。

“不出”的另一个根因是引擎同一批事件先发 `pass`、随后发 `trickEnd`，控制器在通知界面之前清空了展示。现在规则轮转立即完成，上一轮展示保留到下一轮首家**实际出牌**，届时再清除；四个座位都支持“不出”。未添加人为延迟。

贡还页同时接入稳定结果版本、完整交换校验、人工/AI 双门控、本地刷新恢复和只读历史。确认写入失败保持原结果并允许重试。双贡测试还暴露了一个实体牌错误：末游贡牌较大分支从错误的手牌搬牌，导致 108 张只有 107 个唯一实体。已最小修复为各贡牌方移动自己的已选牌，选牌、收牌目标和升级规则未改。

独立代码复核发现并修复：1440 宽度下西家名牌覆盖第一张牌、写盘失败后“继续”永久禁用、损坏历史元数据导致恢复构造函数抛错。损坏历史项现在经过校验和去重，不会使完整的活动牌局崩溃。
