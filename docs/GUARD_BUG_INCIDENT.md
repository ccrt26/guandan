# 事故报告：合法性守卫引用比较缺陷（2026-10-26 发现、修复并定性）

> 本报告按外部指导"发现必须改编码的真实错误时，先停在该具体缺口，给最小修复和影响"的要求撰写。
> 状态：缺陷已修复（最小修复）；受污染的历史结论已全部标记；**未重训、未换正式 AI**；复盘升级（阶段C/D）停在本缺口。

## 1. 缺陷是什么

自对弈/评测脚本中沿用的"合法性防御"写法：

```ts
const legal = legalCombos(state);            // 每次调用返回全新 Combo 对象
if (!move.pass && !legal.some((c) => c === move.combo))   // 引用比较
  move = { pass: false, combo: legal[0] };   // 静默改写为第一个合法出牌
```

`legalCombos` 每次调用生成全新对象（实测同一状态两次调用 46 个候选**逐位置引用相等 0 个**），而 AI 玩家（启发式与神经）返回的 combo 来自其**内部那次** `legalCombos` 调用——引用比较对一切跨调用的非 pass 出牌 **100% 误判为非法**，随后把实际出牌静默改写为 `legal[0]`（枚举序第一=最小压制）。

**影响范围**：所有离线实验脚本（`scripts/selfplay.ts` 自对弈、lab 训练采样、round1/round2 全部评测、搭档筛查、HH 对照）。
**不受影响**：真实游戏（web controller 直连 `applyMove`，按值校验，启发式一直下真棋）；公平性测试（直测 scoreCandidates）；复盘分析器（仅引用建议，无守卫）；引擎本身。

## 2. 发现过程（阶段B验证的意外收获）

接入神经陪练时按外部指导做"加载一致性/合法性"检查：`verify_neural.ts` 用同样的引用比较复检 NeuralPlayer 出牌，688/1220 决策"非法"——顺藤摸瓜发现根因。修复后 0/1220。

## 3. 最小修复

新增 `packages/ai/src/legal.ts`：`isMoveLegal`（值校验：牌在手 + beats() 压制检查，与引擎 applyMove 同规则）与 `guardMove`（非法才回退）。已替换全部守卫点（nnplayer/sampler/round2/checks/diag2/verify_*/selfplay）。typecheck 全绿；修复后采样/评测/陪练链路重验通过。

## 4. 污染定量（lab/guardfix_evidence/）

- 触发率：非 pass 出牌 **100%** 被改写（训练采样 48.8% 决策、历史 selfplay 57.3% 决策——含 pass 的占比）；
- 但改写是否改变实际出牌：神经 44.1%、启发式 61.0% 语义改变（启发式"最小压制"原则使其很多跟牌本就≈legal[0]）；
- 昨晚 round2 结果与旧守卫复现**逐场一致**（首场 win=1/9副/1400手 完全复现），与新守卫（win=0/8副/940手）不同——铁证；
- **训练数据的动作-标签错位**：采样记录的特征向量=网络所选候选，实际打出=legal[0]——网络的"选哪个牌"打分从未获得与动作对应的回报信号，只学到"出/不出"的时机。
