# 事故复盘：2026-10-25 "教练报告胡说"三连

用户连续三轮投诉：①"我没有 4A，你幻觉了"；②"我明明是第一名，怎么成了最后一名"；
③"纯粹胡说八道"。**三起全部不是 LLM 幻觉，是引擎喂了错数据。** 本文档记录根因、修复与防复发措施。

## 事故一：凭空出现的 4A 炸弹建议

- **现象**：报告建议用户"炸 AAAA"（复现卡建议框 ♣A♦A♥A♠A），用户坚称手里没有 4 张 A。
- **根因链**（5 Why）：
  1. 为什么建议 4A？→ 分析器重建的"用户手牌"里有 4 张 A。
  2. 为什么手牌是错的？→ 回放把手牌算错了：出牌被从错误座位的手里扣掉。
  3. 为什么扣错座位？→ 记录里 `player` 字段写的是下家（controller 在 `applyMove` 推进 turn 之后才取 `state.turn` 记录）；回放当时信任 player 字段。
  4. 为什么没人发现？→ 记录器无任何校验；"记录↔回放"无往返测试。
  5. 为什么设计成这样？→ `applyMove` 既变更状态又推进轮次，调用方在变更后取轮次的写法没有被 API 阻止。
- **修复**：controller 先取 mover 再 applyMove；回放改为牌张归属驱动（不变量 I1）。

## 事故二：名次张冠李戴（"我明明是第一名"）

- **现象**：用户的头游局（10:25，胜·第一名）先被判"数据损坏无法复盘"，随后（修归属时中间版本）又显示第四名，用户被连续激怒三轮。
- **根因链**：
  1. 为什么无法复盘？→ 该局由规则重构中途的旧引擎记录（含后来删除的"钢板带两对"牌型），当前引擎判不了型。
  2. 兼容后为什么还算错？→ 旧引擎的轮次结束规则与现行不同，回放状态机的轮次漂移 → 从错误的手扣牌 → handsAfter 对不上 → 被判"损坏"。
  3. 为什么会拿"手牌数对不上"当损坏判据？→ 当时不知道牌张归属可以完全独立于规则重建（id 与 handsAfter 全程自洽，89 手逐手验证成立）。
- **修复**：回放以牌张归属为唯一手牌事实来源；"压不过却出牌"视为旧规则下的新一轮领出。该局现已完整可复盘（评级 S、失误 1/19，与用户记忆一致）。

## 事故三：正文为 0、页面静默回初始态

- **现象**：点"生成教练讲解"，思考 2.9 万字后页面无声回到"待生成"，无报告无报错。
- **根因链**：
  1. 为什么没正文？→ 思考 token 计入 max_tokens（10240），被思考耗尽。
  2. 为什么没报错？→ 前端对流结束但零正文的分支处理是静默 setStatus('idle')。
  3. 为什么额度设这么小？→ 不知道该端点思考无法限量（budget_tokens 被无视、不传 thinking 也思考）。
- **修复**：max 档 max_tokens=32768；std/off 用 `thinking:disabled`（实测约 30 秒出报告）；零正文显式报错+重试提示。

## 防复发（不是补丁，是契约）

1. **checkRecordIntegrity 铁律校验**（engine/record.ts）：108 张合法牌 / 牌张归属唯一 / handsAfter 逐手一致；落盘即跑（controller）+ 复盘入口再跑（ReviewPage）。
2. **schemaVersion=2**：新记录强制 player=归属一致，记录器回归在测试与运行期双门禁。
3. **integrity.test.ts 往返属性测试**：自对弈→记录→校验必须干净；故意复刻"错记下家"与"篡改 handsAfter"必须被抓。
4. **lintReportCards**：LLM 报告中剧本外的牌张 → UI 黄牌。LLM 的职责边界=只组织语言。
5. **ARCHITECTURE.md** 固化全部不变量与"新增数据生产者必须带往返测试"的合入规则。

## 教训（写进流程）

- **先对账数据，再怀疑模型**：LLM"幻觉"投诉的第一嫌疑永远是输入数据。
- **记录器是一等公民**：任何"边玩边记"的代码路径，mover 等关键字段必须在状态变更前捕获。
- **引擎规则演进必须假设历史记录永生**：回放只信与规则无关的事实（牌张 id），不信规则衍生物（轮次/合法性）。
