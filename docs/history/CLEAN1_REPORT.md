## 2. 代码变更与真实运行命令

**变更 1：万能牌当自然牌漏招（窄修复，第四节）**
- 位置：`packages/engine/src/combo.ts` `enumerateCombos` 尾部新增变体块。
- 内容：级牌纯集合（单张/对子/三张/炸弹 4..8）与三带二级牌主体（全自然带对）补充"花 k 张同点万能牌、保留等量自然级牌"的合法物理变体；去重键 = 声明(comboKey) + 物理牌张。此前枚举"真实牌优先"每声明只产出一个物理实现，漏掉该类合法动作（报告原例：级 5 手 ♠5♠5♥5 的 {♠5,♥5} 对 5）。变体只花与级牌同点数的万能牌（双级局 H5 不当 9 用）；"同点不同花副本选哪张"仍为已记录边界（非本类漏招，不修——候选爆炸）。
- 证据：`lab/src/wildcard_repro.ts` 12/12（预期合法动作/枚举遗漏/引擎 classify 接受/385 维编码可区分/候选去重共存）。
- 引擎接受性：classify 对 {♠5,♥5} 与 {♠♠♦♥}炸 均给出同声明解释——变体是真实游戏里人类可选的合法出牌。

**变更 2：isMoveLegal 守卫加固（第三节检查 1）**
- 位置：`packages/ai/src/legal.ts`。
- 内容：牌张多重集校验（同 id 不得重复消耗）、声明张数=实际牌张、声明可复认（classify 能按同 comboKey 重组，拒绝错误牌型描述；万能牌单张按级牌身份放行——classify 对双级局取最强级牌解释为引擎既有口径）。
- 大规模验证：`lab/src/guard_mass.ts` 400 随机手牌（含双级局）19,132 个枚举产物（7,494 涉万能牌）0 守卫拒绝、0 classify 失配、0 候选去重吞并——加固不会误伤任何枚举产物（避免重蹈"守卫改写"覆辙）。

## 5. CLEAN1 训练（第六节）
