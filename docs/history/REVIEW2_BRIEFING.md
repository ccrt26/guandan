### 1.8 统计方法（复算所需全部信息）

- 块定义：每种子打 2 场（NN 方坐 side0 一场、side1 一场，同 matchSeed 派生、座位差固定）；X_s =（side0 胜 + side1 胜）/2，取值 {0, 0.5, 1, 1.5, 2}。**附录 A 用 2X 整数编码（0..4）**，均值 = ΣX_s/(2n)。
- seedblock-bootstrap：对 X_s 数组做块级（每种子一块）百分位 bootstrap，重采样 **10,000** 次，固定种子 **20261027**（lab/src/stats.ts）；置信水平：三档主比较 97.5% 双侧，CLEAN1/NN 评测 95%。
- 退化情形（全胜/全负）回落 Hoeffding：128 块全胜 95% 双侧半宽 = sqrt(ln40/256) = **12.004pp** → [87.996%, 100%]；配对差半宽 ×2；Y 敏感度 0.025^(1/128) = 97.159%（以上公式上一轮已核）。
- 配对差：同种子、同 matchSeed（同初始牌与座位差）下两政策各打一场的 X_s 差；E1 基准比较为新 holdout 上 E1-ck180 与原 ck180 按 seed 配对。

### 2.2 喂给 LLM 的 prompt（现网逐字要点）

**system**（要点）：掼蛋规则速览 → 【铁律：禁止编牌】三条（牌张必须原样引用剧本 / 剧本没写的不提 / 不确定就说不确定）→ 【四层信息，分清来源，不许混称】：

> ①对局事实（当时公开信息与实际出法，可核实）；②引擎建议（启发式中级口径）；③模型建议（ck180 候选排名，是建议不是客观最佳，分数不是胜率）；④反事实模拟（真实手牌条件下、续打用现有启发式的条件结果，不代表当时必赢/必输）。禁止把任何一层说成"客观正确"；禁止把模型排名或模拟结果当成判错的唯一依据。

→ 输出格式（[[MOVE:N]] 标记 + 每手"局面→你打了什么→问题→应该怎么打→影响"；总评→逐手→2-3条建议；800-1200 字）。

**user**：对局信息 → 引擎量化分析（含模型覆盖统计行）→ 关键手复现剧本（≤6 手；每手：轮次背景/本轮此前动作/你打出+判定图标/引擎建议/模型建议行/下一手/各家剩牌）→ 反事实模拟行 → 知识点简报。

### 2.3 已坐实的事故与根因（按时间）

**事故 1（10-25）：编造"4A 炸弹"。** 报告出现剧本里不存在的 4A。根因：记录数据损坏仍进分析，产出似是而非的建议。→ 修复：108 张完整性铁律（validateRecord 前置）+ 牌张 lint 最后防线。已上线。

**事故 2（10-26，用户截图第 25 手）：全篇自相矛盾。** 表现：报告一边说"带错一对，胜率从 100% 掉到 0%"，一边红叉标实际出牌、金框标引擎建议，而模拟数据行方向还抄反。根因链（已定位，**修复未实施**）：
1. **两个"权威结论"互相矛盾且无仲裁层**：analyzer 一阶打分判实际 JJJ+99 失误、建议 JJJ+33（最可能是"不拆牌纪律 −12"撞上 decompose 计划里含 9 的炸弹/同花；若级牌=9 则万能牌 −5+fallback 也可能）；而 runCounterfactual 的确定性续打却给出 99=100%、33=0%——**引擎自己的模拟判了引擎自己建议的死刑**。两者同屏（红叉 99 + 金框建议 33 + 模拟数据行），LLM 被要求"禁止把任何一层说成客观正确、禁止拿模拟当判错唯一依据"，又被要求讲出一个连贯故事 → 只能编。
2. **判罚理由不进剧本**：moveScript 只喂"引擎判定图标 + 引擎建议牌"，不喂 note/tags/scoreGap。LLM 不知道为什么判错，只能自己发明因果（该案例中它脑补"你的 33 是炸弹 3333 的零件"——剧本里 3333 不存在，是把建议里的 ♣3♦3 脑补成炸弹、再把"带 33"安到玩家头上）。
3. **确定性伪胜率**：SIM_CAPS noise=0 → 同分支"40 局"是把同一条确定性对局重放 40 遍（且完全信息），100%/0% 是伪胜率而非抽样估计。
4. **lint 只到牌张层**：裸断言（"3333 是炸弹"方向的语义错误）查不住——牌张 token 合法但断言为假。
5. **知识点对撞**：知识点简报【不拆炸弹】进 prompt 后被 LLM 复述成"铁律"，与金框建议 33 直接对撞。

**仍在现网的缺陷（10-27 核实，D 阶段引入/遗留）**：
- **counterfactual 表头错标来源**：coach.ts 现网文本 `## 反事实模拟（真实手牌平行重演；建议来源=ck180，续打策略=现有启发式版本——条件结果，不代表当时信息下必然`——两处错误：①"建议来源=ck180"**不实**（该分支的建议=counterfactual.ts 里 scoreCandidates 启发式 top-1，与 ck180 无关），与四层规则里"③模型建议=ck180"直接冲突，等于教 LLM 混称来源；②**缺右括号**。
- 事故 2 的根因 1/2/3/4/5 **全部未修**：无仲裁层、判罚理由仍不进剧本、反事实仍是确定性重放、lint 仍只查牌张、知识点仍可能与金框建议对撞。
- nnAdvisor 层（10-27 上线）只解决"多一个视角"，不解决上述冲突。

### 2.4 我的根因总结（一句话版）

**复盘管线把"互相矛盾的两个权威结论 + 不给理由的判罚 + 伪胜率数字"同时塞给一个被禁止仲裁的 LLM，还要求它讲得像老教练——它只能靠编来消解矛盾。** 这不是 LLM 能力问题，是管线设计问题：判罚（裁判层）、建议（教练层）、讲解（解说层）三权没有分立和仲裁。

### 2.5 待拍板修法（已提出未动手）+ 请 ChatGPT 优化的问题

## 3. 神经陪练为何不区分初/中/高（任务 3）

### 3.1 直接回答：**没有去区分**（设计决定），不是不能区分

依据：CLEAN1-REVIEW-1.0 指令 C-8 明确"暂不增加仅对手神经、神经三档"，本实现照办：web 神经开关 = 3 个 AI 座位（含队友）全切 ck180，难度选择器在神经模式下禁用。用户现在提出要分档，这是**需求变更**，技术上完全可做。

### 3.2 技术事实

- `NeuralPlayer`（packages/ai/src/nn/nnplayer.ts）：`new NeuralDecider(seat, mlp, 0, () => 0)` —— 推理 **ε=0、rand 恒 0、纯 argmax、确定性**。单一权重文件 = 单一固定强度。`difficulty` 字段仅为接口占位。
- `NeuralDecider` **已内置 ε-贪婪参数**（eps>0 时以概率 ε 随机出合法牌）：分档的最小实现只是把 ε 和真随机源传进去 + 在 web 层把难度选择器接到 ε 上——工程量约半天。
- 强度数据（对启发式三档的胜率，即"yardstick"口径）：

| 政策 | 对初级 | 对中级 | 对高级 |
|---|---|---|---|
| ck20 | 1.000 (dev) | 0.672 | — |
| ck60 | 1.000 | 0.828~0.938 | — |
| ck120 | 1.000 | 0.891~0.969 | 0.969 (32块) |
| ck180 | 1.000 (holdout) | 0.977~0.984 (holdout) | 0.953 (32块) |
| ck228 | — | 0.938 (dev) | 1.000 (32块, 全胜) |

- **用户体验的量化证据（B2）**：中级启发式作代理玩家，在 3 神经局胜率 **17.2%** [9.4, 25.0]，同代理在中级启发式模式 50% [37.5, 62.5]——神经模式显著更难（配对差 −32.8pp [−46.9, −18.8]）。对人类初学者大概率接近"没法打"，与用户感受一致。

### 3.3 分档方案（请拍板；可组合）

| 方案 | 做法 | 成本 | 风险/备注 |
|---|---|---|---|
| A（现状） | 神经=单一高难挑战档，渐进靠启发式三档 | 0 | 用户明确不满意 |
| B：ε-贪婪三档 | 同一 ck180，ε 初/中/高 ≈ 0.30/0.15/0.05（待校准） | 半天（参数已内置） | 随机合法招≠"较弱但合理的人"，偶有怪招；ε-胜率曲线单调可用 128 块对中级启发式实测校准 |
| C：检查点阶梯 | 初=ck20、中=ck120、高=ck180 | 近 0（权重都在） | ck20 对中级启发式仍 67%——对纯新手可能还是太强；早期检查点棋风未校准；无人类体验数据 |
| D：混合 | 初级=现有初级启发式，中级=ck20 或 ε 噪声，高级=ck180 | 半天 | 产品最平滑；"神经"名义只覆盖中高档需向用户说明 |
| E：专门训练中间强度 | 早停/蒸馏出两档新权重 | 每档约一次 228min 训练 | C-8 曾搁置；在 B/C 校准结果不理想时再启动 |

**我的建议**：B+D 组合先做（零训练）：神经模式下恢复难度选择器 → 初/中/高 = ε 0.30 / 0.15 / 0（或 D 的混合），校准锚点 = **对中级启发式 128 块胜率**（目标如 初级档 ≈35-45%、中级档 ≈55-70%、高级档 =现状），校准数据进 lab/ 留档；E 仅在实测 ε 曲线不单调或体感差时启动。**请 ChatGPT 拍板：方案选择、ε/检查点取值、校准锚点与目标区间、人类体验如何低成本验证。**

## 4. 本地训练是否继续（任务 4）

### 4.1 继续 vs 暂停的论据（全部有数字）

**支持继续：**
1. loss 未收敛（6.02→5.04、5.57→5.33，且曲线噪声大、无明显平台）；DMC 类方法 1,500 万决策对 16.5 万参数的 MLP 远未到常见收敛量级。
2. **最明确的改进对象在动作空间而非更多同质样本**：候选枚举的 class-2 缺口（§1.7——62% 首牌候选存在未列的资源不同变体，如留 ♥8 保同花顺的 {♠8,♦8}）。修复后 MDP 本身变了，重训有理由期待真实提升；且训练与复盘共用候选集，nnAdvisor 的覆盖率/质量同步受益。
3. 自博弈单一流派可能自我强化盲区（对启发式 95%+ 但 yardstick 已饱和，无法察觉停滞），对手池化是标准解法。
4. 成本仅本地 CPU（228 分钟/run），不与任何外部资源竞争。
5. **规则正确性**：级牌口径已改官方 'stage'，而 ck180 训练于旧 'both' 世界（§1.4 披露）——无论棋力论述如何，重训到正确规则世界这一步本身就成立。

**支持暂停（或先做别的）：**
1. **yardstick 饱和**：对中级 97.7~98.4%、对初级 100%、对高级 95~100%（CI 重叠）——同配方继续训练**无法用现有基准度量进步**，练了也说不清有没有变强。
2. E1 复制显示 dev 阶梯两个 run 高度一致（都在 ck180 附近到顶、ck228 回落），提示配方在该预算下的产出已稳定，边际收益低。
3. 产品的两个用户可感瓶颈——复盘胡说八道（§2）、神经无难度阶梯（§3）——都是**决策与工程问题，不是算力问题**；先修它们对用户价值远大于棋力再涨几个点。
4. 同配方再加时长的收益逻辑存疑：ck228 在两个 run 都不优于 ck180。

### 4.2 我的结论

**训练要继续，但不是"照旧继续"**：同配方堆时长的边际收益趋零且无法度量；有意义的下一轮是"改目标再训"（候选 v2 + 对手池 + 自博弈 Elo 作为超越启发式饱和的新 yardstick），且排在两个产品修复（P0）之后。机器闲着也不亏：P0 不占训练算力，可并行。

### 4.3 分阶段方案草案（请 ChatGPT 优化）

**P0（本周，零训练）**：
- P0-1 复盘修法 §2.5 的 ①④ 立即修（仲裁层 + 表头 1 行），②③⑤ 按拍板结论实施；
- P0-2 神经分档 B+D 上线 + ε 校准评测（128 块 × 对中级启发式，3 档）。
- 验收：复盘报告在 3 局真实对局上无牌张层错误、无来源混称；分档胜率落在目标区间。

**P1（下一轮训练，CLEAN2，P0 完成后或并行空闲启动）**：
- **在 'stage' 规则世界重训**（规则正确性独立于任何性能考量：现部署 ck180 训练于旧 'both' 世界，§1.4 披露的训练/部署错位）；

- 门：一致性计数五项全零；dev/holdout 不低于 CLEAN1 同口径；自博弈排名新模型 ≥ 旧 ck180；

**明确不做（未经复查方批准）**：加大网络、改标签结构、改编码（pass 位 quirk 封存不动）、多轮超参搜索。
