## 0. 速览

**目标**：本地掼蛋游戏中，三个难度档之间存在稳定、可解释、玩家实际能感受到的牌力差距（本游戏内的相对强弱，**不冒充真人段位**）。

**两条路线**（详见 §10，由用户选择，本轮都不执行）：

| | 推荐路线（需授权装依赖） | 零新增依赖备选 |
|---|---|---|
| 做法 | 游戏与引擎保持 TS；在**隔离目录**用 PyTorch（Apple 官方支持 M 系芯片 GPU 训练，无独显≠不能用 GPU）做离线训练与模型转换，产出权重接入 TS 游戏端推理 | 修复可证实问题 + 廉价特征改善 + 预算受控的启发式调参；或一个很小的纯 TS 模型 |
| 依赖 | PyTorch（隔离 venv，不碰游戏包） | 无 |
| 适用 | 若候选复用/训练确认要走 RL | 若用户坚持零安装，或 RL 试验无增益 |

**候选复用资源（新增，须先隔离验证）**：社区仓库 `Choysang/rlcard-guandan` 内有 **DanZero 权重文件**（q_network.ckpt，约 5.3MB）与 Release 的 PerfectDan 权重（约 73MB）；`Calix-L/CardKS` KSCB 数据集有真人掼蛋 899 场/10,218 副/840,194 决策点。**均为候选，未验证适配性与牌力**，详见 §4。

**阶段顺序（§11）**：A 事实核对与方案修订（本轮）→ B 修复+评测基建+候选验证（需授权）→ C 性能与小学习试验（30-60 分钟→2-4 小时预算）→ D 有实测增益才追加 → E 留出评测后回填三档。

## 1. 目标与术语

**主验收指标**：完整升级对局（从 2 打到过 A 的整场）的**队伍胜率**。单副胜率、升级分只作补充指标。若阶段试验只训单副，只能报告单副能力，不得宣称提升了过 A 策略。

**术语（全文统一）**：
- **决策点**：一次出牌或过牌的选择（一副牌约 155.7 个决策点，实测均值）；
- **单副**：108 张牌发 4 家打完一副（引擎 `startGame`→`over`）；
- **完整升级对局**：多副连续打完、直到一方过 A（引擎 `MatchState` 层）；
- **样本**：一个 (观察快照, 候选动作集, 选定动作, 标签) 元组，以决策点为单位。

## 5. 规则核对与输入表达

### 5.1 规则核对结论（本轮已核）

本地引擎与《掼牌（掼蛋）竞赛规则》口径的关键项已核：级牌为**本副状态**（`makeLevelCtx`，非由两队级数较大者简单推断）；王对不能压炸弹；一大王+一小王不成对；进贡合法优先（红心级牌外最大牌），还贡合法集 2..10 内取**点数最小的一张**（代码实际行为，可能拆对；10 合法）；借风/首出权由引擎 `trickEnd`/`applyTribute` 处理。**待办**：与外部参照（淮安市地方标准 DB3208/T 235—2025，仅作交叉提示非国家标准替代）逐条比对一遍边角（过 A 三模式、同花顺与多张炸弹比较序），发现差异只报告不擅改。规则原件（名称/版次/发布者/原件位置）在阶段 B 归档登记。

### 5.3 动作编码（每候选，**已实现**）

| 字段 | 维数 | 说明 |
|---|---|---|
| 实际消耗物理牌 | 54 | 0..2，**不是**宣告后的虚拟牌面 |
| 宣告牌型 | 11 | one-hot（10 牌型 + pass 专用档） |
| keyRank | 1 | /41（rankOrder 域：普通 2..14、级牌 20+rank、小王 40、大王 41） |
| 张数 | 1 | /10（两副同点炸弹最大 8 张，覆盖全部合法牌型，**无截断**） |

**物理消耗与宣告分开**（反例）：同一对子宣告，一个耗万能牌一个保留万能牌，出牌后剩牌不同——不合并为同一候选特征；同一物理牌的不同合法宣告同样保留。候选去重键 = 物理计数向量 + kind + mainRank + length + pairRanks（`lab/src/seat.ts dedupCandidates`，证明语义等价后才去重）。实测去重后候选数 p50=2、p95≈17-20、p99=33、max=114（lab/out/bench_report.json）。

### 5.4 起点网络（**已实现**）

`385 → 256 → 256 → 1`（tanh 隐层、线性输出）。TS 前向（`lab/src/mlp.ts`）与 PyTorch learner 权重逐位一致：实测 64 样本最大绝对差 **2.1e-7**。参数含偏置 **164,865**；纯权重 float32 文件 659,460 字节（≈0.63MiB；含优化器状态的恢复包另计，实测数百 KB～MB 级）。推理输出是"当前训练目标下的评分"，**不得称为获胜概率**。

## 6. 可见信息边界（反作弊）

1. 正式 Player 只接收：自己手牌 + 公开观察 + 合法动作列表。现有 `AIPlayer.decide(state: GameState)` 传全量状态（含他家手牌）——NeuralPlayer 实现时**必须**走受限适配层：从 state 只提取 §5.2 字段（特征提取函数只读白名单字段），不缓存他家手牌，不比较他家牌数组。共用权重 ≠ 共用四家私有记忆：各家实例的记牌器/历史缓冲独立。
2. 训练样本的观察须在**决策时刻复制快照**（值拷贝，不存会继续变化的数组引用）；终局打标签时**不得**用"已看到全部后续出牌的记牌器"重建早期输入。
3. 验收测试（阶段 B 新增，比现有 fairness 更细）：构造公开历史、己方牌、各家余牌数、贡还信息均相同且牌组守恒的两个可能世界，改变队友与两家对手的隐藏牌分配；固定决策随机数后，比较**观察编码逐位一致、候选语义集合一致、各候选评分一致、最终动作一致**（不只比 argmax）。另测 observe/reset 隔离与玩家间缓存隔离。
4. 环境作为裁判可保存全牌、事后生成标签；禁止的只是把决策者当时无权知道的信息送进决策链。

## 7. 训练定义

### 7.1 回报与标签（本项目设计，参考文献口径）

- 每条样本从**决策者本队视角**记账：`y = g + W`。g 的精确定义：设 X = 赢方头游者的队友在本副的名次（二游 / 三游 / 末游），则赢方 g = +3 / +2 / +1（对应引擎升级数：双上游 3 级 / 头游+三游 2 级 / 头游+末游 1 级），**输方 g = −3 / −2 / −1（同一 X 取负，不按输方自己名次另行定义）**；W = 本完整升级对局本队最终胜负 ±1（**仅当完整对局结束才赋值**）。队友视角同号、对手视角反号；**不把四席标同一全局正奖励**，也不丢"先出完者之后本队结果"。
- 该混合标签与 DanZero+ 论文口径一致，但**它不是"最大化最终胜率"的等价目标**；保留单副分 g 与整场胜负 W 两个原始字段，若走训练路线，与"仅 W"目标做一次小型对照后正式定型。
- 中断/超时/未完成对局**不编造标签**，单独记录并规定舍弃/恢复方式。不奖励"永不炸队友""从不拆炸弹"等绝对行为（会压制合理战术）。

### 7.2 BC（可选起点，不再是默认必经）

- 教师不预设为中级启发式：候选教师=现有最强合法启发式（按多对手评测与错误案例选出）、经验证的外部策略、清洗后的人类牌谱（KSCB 若可用）。
- BC 数据必须保留**决策时的完整合法候选集**（或足以精确重建），做全候选 softmax 交叉熵；仅存 (s, a_teacher) 不够。
- 监控：留出集交叉熵、合法候选内与教师动作一致率、实战对教师非劣、对多对手池相对表现。**删除** v1 的"vs 初级>70% 且 vs 中级 45~55%"组合门槛（中级对初级本就无此差距，门槛无基线依据）。
- BC 的 softmax 分数**不是**校准的回报 Q 值：切换 DMC 时明确保留哪些层、输出头如何重拟合/缩放，监控切换后的行为骤变与饱和。
- 初始化对照只做两组：随机初始化 vs 一次 BC 初始化，不做大规模网格搜索。

### 7.3 DMC 最小闭环（先小后大）

- 首期：小网络（§5.4）、少量 actor（2~4）、单 learner、**只实现一种优化器（RMSProp，按作者代码：lr 1e-3，eps 1e-5）**、普通 MSE 回归（**不启用任何 Q 裁剪**；若日后引入任何裁剪/奖励改造/重要性加权，须给完整公式+受控对照，不复制名字或常数）。
- 每副/每场开始时抽定各席行为模型（当前网络/历史合格模型/固定启发式），保持到预定边界，不逐步无记录切换；对手与**搭档**都要混（避免只会与自己配合）。
- 探索：ε-greedy 只在合法动作内；必须领出时 pass 不存在；跟牌时合法 pass 有战略意义**不删除**。探索日程（起点 ε=0.05 衰减至 0.01）以小对照调，不硬编码启发式偏好为"永不可探索"。
- MC 不自举 ≠ 无离策略偏差：旧轨迹来自旧对手/旧搭档/旧后续行为。用**新样本占比、策略版本数、训练复用率**管理，不用"半天"这类时钟阈值描述陈旧性。
- 样本走内存队列直通 learner（**不常驻落盘**，§8 磁盘账）；**队列上限 50,000 条，溢出丢最旧并计数上报**（防内存膨胀；丢弃造成的样本分布偏差显式记录，不做静默阻塞）；learner 每积累 N=2048 条新样本更新一步、batch=1024（复用率 0.5，把 learner 算力账做平，§8）。这些数值为**本项目自行配置**，随吞吐实测调。
- 断点：保存权重、优化器状态、配置、计数、RNG 状态、已完成轨迹处理进度；不保存整池（可承受重放损失）。**不宣称任意 kill 零损失**。文件采用完整替换写 + 保留最近 K 份可读 checkpoint。
- 导出：训练侧 checkpoint 与部署权重格式分开（float32 二进制 + 维度与 schema 版本号，部署文件预估 <1MB；float32 字节数≠JSON 文本体积）。部署前对同一批正常/边界局面核对训练端与 TS 端评分排序一致、动作一致，并计加载与推理时延。

## 8. 算力与预算（复算后；均为条件估算，实测前不是承诺）

以下按 §5.4 网络（464→256×2→1，参数 185,089、纯乘加 184,576/候选前向）：

| 项 | 数值 |
|---|---|
| 每候选前向 | ≈0.37 MFLOP（TS 实测含编码整链 ~1ms/决策） |
| 每副推理（20 候选均值×155.7 决策点） | ≈1.15 GFLOP（不含动作枚举与特征编码开销） |
| 单副墙钟 | **实测**（bench E2E，随机/早期网络）：3498 副/8 分钟 ≈ 137ms/副（26223 副/小时，远优于纸面估算；候选 p50 仅 2） |
| actor 产能 | **实测**：单 actor 单线程 ≈1027 决策样本/秒、约 63 副/分钟（bench 8 分钟） |
| learner 负载 | **实测**：CPU 一步 2.8ms（p95 4.2ms）；MPS 同批 5.7~16.6ms——**小模型 CPU 明显更优，learner 定 CPU**；采样完全主导，learner 占比 <0.1% |
| 训练复用率 | 1024/2048 = 0.5（v1 为 4.096） |
| BC 成本注意 | 每决策点须对**全候选**前向+交叉熵，不能按 DMC 单动作回归口径估算 |
| 磁盘 | 样本不落盘；checkpoint <1MB×K 份 + 评测记录，MB 级/日（v1"1.6KB×百万级样本落盘"= 12.8~36.8GB/日，**已废弃**） |
| 内存 | **实测**（1 actor + 1 learner）：Node 256MB + Python 257MB（统一内存下合计约 0.5GB，余量充足） |

**性能试验计划（阶段 C 入口，30-60 分钟预算）**：测"生产+学习同时运行"——① 合法动作生成耗时与候选数 p50/p95/p99/max；② 选牌时延（普通/逢人配富/领出/残局分场景）；③ 前向/反向/更新耗时（BC 与 DMC 分开）；④ actor 有效样本/秒、learner 接纳与消耗速率、队列长与策略滞后版本数；⑤ 峰值 RSS、内存压力、swap、磁盘 IO；⑥ 持续吞吐衰减与用户同时使用的影响。

**学习试验（性能试验通过后，2-4 小时预算）**：小模型 + 少量 actor，按 §7.1 标签跑 DMC，观察开发集曲线。**短试验无进步不证明 RL 无效**，只用于定位实现/目标/吞吐/探索问题，并决定是否值得追加预算。连续数个预约定评估点无改进→先诊断，不默认延长挂机；始终保留最后已验证可用模型。

## 9. 评测协议与难度分档

### 9.1 档位定义

三档=**本游戏内由弱到强的稳定相对牌力**（能力目标：初级=能力受限完整策略；中级=+记牌与基础配合；高级=+规划与推断）。无可靠人类水平标签与真人对照前，**不宣称"高级=民间高手/职业"**；"旧启发式失误像人"未经真人数据或试玩支持，只作待验假设。禁止用发坏牌、读暗牌、暗中调节难度、随意 pass、可赢送输制造分档。

### 9.2 两类自动评测

1. **整队评测**：两名同款 AI 组队，对固定多风格对手池（现有三档启发式 + 随机 + 历史 checkpoint）——测队伍强度；
2. **单席替换配对比较**：新 AI+固定搭档 vs 相同敌方，与旧 AI+同搭档对照——测个体强度并隔离搭档因素。
另留至少一种**未参与训练/调参/checkpoint 选择**的搭档风格，仅最终验收用（若据其结果继续调参即转为开发池）。

### 9.3 种子与统计协议

- 规则版本与评测策略固定后，**预生成独立发牌种子组**；同组内交换双方阵营、轮换起始座位；发牌 RNG 与策略探索 RNG 分开。
- 独立样本单位=**发牌种子组/完整对局**；同副内多步、同场内多副、四席重复记录有相关性，不当独立 n。CI 按种子组成组 bootstrap，报告组数与总局数。
- 三套种子分离：训练、开发评估（选 checkpoint 用）、最终留出（选型后一次性验收；用过即降级为开发集，不得再称独立留出）。
- 报告：胜率矩阵、平均升级分、完整对局胜率、混搭表现、合法性（0 违例）、时延。随机对手单独报；主要对手池与汇总权重**事前**确定。Elo 仅作摘要，存在克制关系时用矩阵明细替代，首期不建环检测系统。

### 9.4 分档阈值（产品目标，非论文保证）

相邻高档对低档点估计 ≥55~60% 且 95%CI 下界 >50%，对共同对手池与混搭评测无关键退化。1000 副点估计 55% 只证明"有优势"方向，不证明真实胜率 ≥55%——若要求 ≥5pp 实际优势，按下界对相应标准解释。样本量/停止条件**事前**约定（最终验收候选：≥1000 独立发牌组），不因差一点过线追加、过线即停。无合格中级 checkpoint 时，保留现有已验证策略或承认暂时只有两档，**不把早期乱打模型包装成初级**。游戏 UI 中"对手难度"变化时用户搭档保持同一已验证水平，搭档水平若可调则单独设置。

## 10. 两条路线（用户选择）

| | 推荐路线 | 零新增依赖备选 |
|---|---|---|
| 改动 | 游戏与引擎保持 TS；隔离目录（不进 npm workspaces）用 PyTorch 训练与转换；TS 端只加权重加载+前向 | 修复 §11-B 核查出的问题；加强廉价手牌结构特征；预算受控的启发式参数优化；或很小的 TS 模型（性能试验先行） |
| 现有功能影响 | 正式三档与游戏主体不变；游戏端**新增**实验性权重加载/受限观察接口（不替换正式 AI，同结构/编码版本的新模型可换权重更新） | 无 |
| 依赖 | PyTorch（隔离 venv；Apple 官方支持 MPS，M4 可用 GPU 训练；CPU vs MPS 谁快须实测，不承诺倍数） | 无 |
| 验证 | §9 全协议 + 训练端/TS 端一致性核对 | 同左 |
| 失败保留 | 现有三档启发式不动 | 同左 |
| 预算 | 阶段 C 的 30-60 分钟性能试验 + 2-4 小时学习试验起步 | 同左（或更小） |
| 候选复用 | rlcard-guandan 权重/KSCB 数据若验证可用，可能只需转换+适配，**先比较总成本再决定是否自训** | 候选权重的转换仍需一次性隔离环境（与"零依赖"冲突时如实告知用户取舍） |

## 11. 阶段与停止条件

- **A（本轮）**：事实核对、勘误、候选资源审查、修订三份文档。✅ 完成。
- **B（需用户授权实施）**：核查启发式开关真实生效性与候选裁剪影响；归档规则原件与外部标准比对；建 §9 评测基建（种子组/两类评测/三套种子）；新增 NeuralPlayer 反作弊细测；候选资源隔离验证（rlcard-guandan 权重结构还原、KSCB 可重建性）；导出/一致性工具。只做解决具体风险所需的测试。
- **C（需授权+预算）**：性能试验 → 2-4 小时小学习试验（**单一 DMC 基线，随机初始化**；BC 后置，不与本轮混排）。不启动长挂机。
- **D（有实测增益才做）**：批准预算内继续，对手/搭档池保多样性，选稳定模型。
- **E**：独立留出评测 + 推理一致性 + 公平性 + 浏览器实际延迟 + 少量真人试玩，然后回填三档。上线范围由用户授权决定。

**暂停条件**（触发即停并报告事实）：规则口径无法确定；输入/候选存在隐藏信息泄漏；候选编码混淆未解决；训练数值失效；内存/时间超预算；候选资源来源/规则/推理边界不足以验收。外部某资源不可用不阻塞整体修订。
