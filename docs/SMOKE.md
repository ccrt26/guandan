# 冒烟清单（改完界面/存储/报告相关代码后跑一遍，约 5 分钟）

前置：`npm run dev` 起服务，打开 `http://localhost:5180/?autopilot=1`（自动驾驶仅开发模式可用；生产构建忽略该参数）。
浏览器底部出现红色错误条 = 任意一步直接失败（开发模式已把运行时报错钉在页面底部）。

| # | 操作 | 期望 |
|---|---|---|
| 1 | 首页选「中级」，点「开始比赛」 | 进入牌桌，状态条出现「🤖 自动驾驶（测试模式）」，四家自动出牌（延迟约 0.1 秒/手），约 20~40 秒打完整局；控制台无 `[record]` 完整性报错 |
| 2 | 结算模态框 → 点「复盘本局」 | 复盘页顶部显示正确胜负与名次顺序；时间轴点数与手数一致 |
| 3 | 时间轴「下一个我的决策 ⏭」连点 | 只停在人类座位的手上，详情面板显示你打了什么/建议什么 |
| 4 | 切到「教练报告」tab → 生成（标准档） | 思考→写正文进度可见；完成后出现带复现卡的报告，**底部红条无报错、无"剧本之外的牌"黄条** |
| 5 | 生成中途切「回放」再切回 | 进度不丢、不中断（tab 不卸载） |
| 6 | 关闭标签页 → 重新打开同一局复盘 → 教练报告 | 报告**直接可见**（localStorage 持久化，无需重新生成） |
| 7 | 「历史与复盘」→ 删除刚才那局 | 再进复盘列表该局消失；（开发者工具查 localStorage）`gd_report_v2_{该局id}` 键同步消失 |
| 8 | ⚙️ 设置弹窗 | 首页/牌桌/历史/复盘四个视图都能打开与关闭，Key 输入框是密码型 |
| 9 | 打开损坏记录（若有旧版本记录） | 显示「该记录无法复盘：<原因>」，而不是空白或错误建议 |
| 10 | autopilot 打完 ≥2 局（结算后点「下一局」继续）→ 中途第 3 局刷新页面 | 首页出现「⏸ 有一场比赛进行中」卡片（级数/局数正确）→「继续比赛」回到牌桌、第 3 局重新发牌、进贡按上一局结果正常走；「放弃」则卡片消失 |
| 11 | `npm test` | 98 项全绿 |
| 12 | 休眠自愈：把 autopilot 局挂后台 >1 分钟再回来看 | AI 回合若被宿主挂起吞了计时器，回到前台（focus/visibilitychange）后 5 秒内自动继续，不永久卡死 |

注：in-app 浏览器面板长时间不聚焦时，宿主可能吞掉页面已排定的计时器，autopilot 对局会暂停——回到前台自愈（看门狗+事件复活双保险）；这是宿主行为，不是游戏 bug。

自动化程度说明：第 1 步的"打完一局"由 autopilot 代劳（最耗时的部分）；2-9 仍需人工点按——这就是当前零依赖方案的上限，组件级自动化（方案 2b）需另行批准依赖。
