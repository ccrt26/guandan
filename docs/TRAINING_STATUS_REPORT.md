## 2. 核心事件：守卫引用比较缺陷（全部历史胜率失效的根源）

### 2.1 机制

自对弈/评测脚本沿用的"合法性防御"：

```ts
const legal = legalCombos(state);                    // 每次调用返回全新对象
if (!move.pass && !legal.some(c => c === move.combo))  // 引用比较，跨调用必 false
  move = { pass: false, combo: legal[0] };           // 静默改写为最小压制
```

实测同一状态两次调用 `legalCombos`：46 个候选**逐位置引用相等 0 个**。AI 玩家（启发式与神经）返回的 combo 来自其内部那次调用——引用比较对一切跨调用的**非 pass 出牌 100% 误判为非法**，实际出牌被静默改写为 `legal[0]`（最小可压牌）。

### 2.2 影响范围

| 受污染（全部离线实验） | 不受影响 |
|---|---|
| scripts/selfplay.ts 自对弈（含历史"5000 局三档≤3pp"实验） | **真实游戏**（web controller 直连 applyMove 按值校验，三档一直下真棋） |
| Round1/Round2 全部训练采样与评测胜率 | 公平性反作弊测试（直测打分函数） |
| 搭档筛查、HH 对照、炸弹诊断 | 复盘分析器（仅引用建议，无守卫路径） |
| **训练数据本身**：特征向量=网络所选候选，实际打出=legal[0] → **动作-标签错位**，网络的"选哪手"打分从未获得与动作对应的回报；只学到"出/不出"时机 | 引擎规则、候选枚举、吞吐量级、TS↔PyTorch 数值链路 |

### 2.3 发现与铁证

- 发现路径：阶段 B 接入验证（外部指导要求的"合法性检查"）中，NeuralPlayer 688/1220 决策"非法"→追查根因；
- 铁证 1：`legalCombos` 两次调用对象逐位置引用全不同；
- 铁证 2：量化改写影响——神经非 pass 出牌 100% 被触发改写、其中 44.1% 语义改变；启发式 61.0% 语义改变（启发式"最小压制"原则使部分跟牌本就等于 legal[0]）；
- 铁证 3：旧守卫复现器**逐字段复现**Round2 存档首场（win=1/9 副/1400 手），新守卫给出不同结局（win=0/8 副/940 手）；
- 铁证 4：manifest 哈希绑定"代码版本↔结果文件"。

### 2.4 修复（最小修复，已全部落地）

`packages/ai/src/legal.ts`：`isMoveLegal`（值校验：牌在手 + beats()，与引擎 applyMove 同规则）+ `guardMove`（非法才回退）。替换全部守卫点（nnplayer/sampler/round2/checks/diag2/verify_*/selfplay/review 测试）。typecheck 全绿、**全量 98/98 测试通过**、修复后链路复验 0 非法。独立复查确认修复与引擎校验等价、回退路径安全、三项"不受影响"定性属实。

**过程插曲（两次同类失误）**：字符串替换式补丁两次静默未生效（round2.ts 守卫、controller 接线）——分别靠"逐场对账"和"独立复查"发现后用精确编辑重修。教训已入项目记忆：**补丁必须 assert 匹配成功**。

## 3. 修复后的真实基线（一切归零后的实测）

| 实验 | 结果 |
|---|---|
| ck1 / ck3 / final 对**真中级**启发式（各 100 整场） | **全部 0 胜** |
| armA_end 与 final 对**初级**启发式（各 24 场） | **均 5 胜（21%）** |
| **测试台验证**：真中级 vs 真初级（同台同协议，24 场） | **24/24（100%）** |

三个关键认知：
1. **受污染训练产出的模型真实棋力低于初级档**（动作-标签错位使选牌能力从未被训练）；
2. **修复后的评测台具备完全区分度**（真中级对真初级全胜）——今后数字可信；
3. **"启发式三档差距≤3pp"的旧结论死亡**：那是三个 legal[0]-bot 在比 pass 纪律。启发式档位间真实差距目前只知"中级≫初级（24/24）"，**高级与中级的真实差距从未被测过**。

## 4. 现在确定知道什么

**有效结论**（不受缺陷影响）：规则引擎正确性（规则锁测试）；三档启发式在真实游戏中的行为；公平性边界（平行世界测试，迁移到正式包后复验通过）；nn 基础设施全部可用且已验证（唯一权威实现位于 packages/ai/src/nn/：编码/前向/决策器/NeuralPlayer；加载逐字节一致、决策确定性、时延 p50=0.3ms/p95=2.4ms）；TS↔PyTorch 数值一致；评测吞吐（整场 0.3-0.7s/场）；浏览器实跑整局无卡顿；forced 占比 32.9%（31.8% 为规则性只能过）；候选枚举完整性（穷举法验证，真漏招仅"万能牌当自然牌"一类，记为已知边界不修——修了会改候选集导致权重失配）。

**失效结论**（已加横幅存档）：全部对局胜率、三档差距、A/B 利用率结论（仅在污染体制内成立）、炸弹行为诊断（记录的是改写后的 legal[0]）。

**新增可用资产**：值守卫工具（legal.ts）、阶段快照机制（snapshot_round2_*.ts）、统计核对脚本（含回归测试）、lab/round2_bugregime/ 污染证据存档、事故报告 docs/GUARD_BUG_INCIDENT.md。

## 5. 当前困境（待外部意见的核心）

1. **模型作废**：三个存档+两臂全部低于初级。神经路线需从零重训才有意义；
2. **配方信心问题**：Round1 配方是在污染数据上跑的——好消息是它即便数据错位也学出了"出/不入时机"（loss 从 8.5 降到 3.8），说明管线与优化器工作正常；坏消息是"选牌"部分从未被真正训练过，同配方在干净数据上的表现**完全未知**（可能更好——信号终于对齐；也可能需要调整）；
3. **基准认知重建**：启发式档位真实差距未测（中级 vs 高级整场口径零数据）——它既是神经训练的对标，也是"档位差距"产品目标的现状基线；
4. **成本约束**：个人项目。重训一轮 228 分钟纯机时+人工监控；评测基建现成（修复后测试台+整场协议+种子管理）。

## 6. 我们的初步计划（供外部批评）

**方案 R1（推荐）：同配方干净重训一轮**
- 与 Round1 完全相同的配置（385 维/256×2/ε=0.05/利用率 0.5/g+W/RMSprop），仅数据管线为修复后版本（特征=实际出牌，首次对齐）；
- 预算：训练 228 分钟 + 整场评测（3 存档×100 场≈5 分钟）+ 对初级/中级定位（≈3 分钟）；
- 事前固定：评测种子（沿用修复后测试台）、检查点 60/120/180 分钟、成功标准（对初级整场 >50% 视为"学到选牌"，否则配方需归因分析）；
- 不做：A/B 对照（等主实验有信号再说）、网络扩容、BC（见 §7-2 讨论）。

**方案 F：冻结神经路线**
- 游戏与复盘维持现状（不受缺陷影响，照常可用）；神经陪练 UI 开关保留（文案已如实标注"待重训"）；
- 顺带补做：启发式档位真实差距测量（高级 vs 中级 vs 初级整场各 100 场≈6 分钟）——重建产品基线，也回答"高档到底比中档强多少"。

**两案共同的前置小实验（可选，~10 分钟）**：干净管线下跑 20 分钟冒烟训练，确认"特征=实际出牌"后 loss 能正常下降、无其他管线意外，再决定投入 228 分钟。
