### 2 全程状态契约

状态只能是not_started、not_implemented、ready、running、completed、verified、reused、blocked、incomplete、failed。completed表示进程正常结束，verified要求消费具体证据的独立核验入口通过。reused必须指向完全相同身份的已核验工件。所有blocked有机器可读原因、缺失依赖和不受影响的下一任务。

每张收据至少包含taskId、cycleId、输入输出全长SHA、sourceSnapshotHash、完整政策身份、实际argv、开始结束时间、退出码、资源实耗、验收器及其SHA、证据文件列表。收到一个布尔verified字段不能自我背书。报告程序只汇总收据，不自行把missing改pass。

stageStatus与resultCode分开。例如stageStatus=completed、resultCode=window_saved表示运行窗已保存，targetCompleted=false；不能将window_saved塞进状态枚举冒称训练完成。stageStatus=verified只表示该任务验收通过，policyEligible由完整晋级规则另判。

所有命令严格解析：未知参数、空路径、NaN、Infinity、负数、非整数更新数必须在spawn前拒绝。按阶段解析schema：inspect/backup/工程验收/pilot接受--config草案；生产build-teacher-data/train-window/evaluate-dev/confirm必须有--protocol锁文件。草案允许尚未产生的身份为空；已锁必填字段不能空，可选LLM禁用字段和运行后收据按CONFIG_README处理。训练不得回落默认protocol-v3。子进程非零必须上传播；主进程失败时只能终止自己登记的子进程。不得pkill所有node/python。禁止后台失联跑训练。

### 3 三条禁止改写的边界

不能删旧证据、不能把本轮偏差改写成原轮合规、不能因未完成而降低验收门或改分母。可以做最小修复、恢复和开发迭代；影响规则、数据、网络或评测的实质变更必须先升协议身份。已授权的工程修复不需要反复问用户；新增付费服务、超出现有明确费用上限或正式替换部署属于另一个具体动作，不夹带执行。

使用冻结label函数y=g+W：g为当前根点所在本副本队名次升级分±1/±2/±3；W为完整match本队胜负±1。取z=(y+4)/8仅用于归一化证据展示；训练Q仍是原y尺度。不是把整场所有g求和，更不是按我个人先走给分。每世界、每分支用同一组之后发牌随机流；状态分岔时允许轨迹不同，但不能偷偷选更好未来牌。

每世界差d=z(A)-z(B)，配对重采样按世界而非action。初版20,000次固定seed配对bootstrap，取97.5%双侧区间；明确这是经验区间，非分布无关真理。标签支持要求主续打下界>0.02，第二续打下界>0；不足记ambiguous，不给负标签。0.02是教学最小效应工程提案，相当于原y尺度0.16，起跑前锁定。每根只验证探索时选中的一对，不能用验证世界再选赢家。

统一统计实现：percentile bootstrap，等概率有放回采样独立单位，20,000次；分位使用线性插值（R type 7），实现版本和seed写入lock。同一根的两动作始终共用重采样索引；主与第二续打各用自身预锁世界。保存原始d与输出分位，独立recompute验证。禁止换BCa/单边/分位法挽救边界标签。

有未完成分支、非法采样、暗牌泄漏或未来输入，该root不得生成强标签。局部残局证明、只评本副g、截断叶估计可单列为近似教学研究，不偷换完整g+W口径。跨root同时有许多标签时不声称每一条均获得总体95%保证；保留置信度、错误抽查和后续泛化检验。

LLM是可选候选提议器：发送版本化JSON可见事实，输出计划与动作ID；先校验，再搜索。已有费用上限明确时复用用户已授权连接。调用请求、失败重试、token、价格版本、花费都入账；无明确上限则本地教师继续，API子模块blocked_cost_config。两个LLM一致不能免搜索，也不证明高手认可。

产物为teacher-pilot.json、plans.jsonl、world-manifests.json、branch-results.jsonl、teacher-labels.jsonl、teacher-rejections.jsonl。教师产出率按合格去重root/秒，独立源match/家族另计，绝不能用几十万个分支当几十万教学题。

teacherQualityReceipt最低要求12根完整收据全都有明确结果、规则/信息集/动作身份负例全过，并至少获得4个supported根动作、来自至少3个源match或构造family，包含至少一个“让优于接”和一个“接优于让”。这些是双向教学链的工程覆盖门，不是教师准确率证明；不足就如实诊断，不能降低区间或造标签。pilot开始前可以另登记最多48个候选根作为补充探索队列，到界仍不足则teacher_not_ready；已花成本全部算入，不无限追加。第一份正式标签批再按预锁随机抽取10%（至少10个、最多50个；总数不足10取全部）做新世界独立复核，报告方向失败率；出现规则/泄漏问题整批隔离，统计不支持只剔除该标签并重算规模，不重抽有利复核世界。

### Task 7 评测与候选封存

三组训练外搭档先登记：独立冻结政策、未参与训练的人类代理或可核真人来源、未入训练的策略风格。每组需完整身份和共享来源说明；同一H换seed不成为另一种独立人类风格。no_h分支允许在起跑前登记三组非真人冻结搭档做正式自动研究确认，但不声称人类兼容性已验收；不得在with_h成绩不好后换组。三组开发搭档与三组确认搭档角色分开，确认配置不得用于调参。

主指标是完整match teamWin，候选N与旧完整包O各自搭同一H，对相同冻结对手池。每基础块包含三个组的配对比赛，每组N/O都做两场换边；底层初始牌一致，后续每副的发牌由独立dealId派生，不能因先前RNG消费不同造成下一副不同牌。块内12场是相关观测，统计只算一个基础块。每组差值D_j=mean(win_N两场)-mean(win_O两场)，主差D为三个D_j宏平均，范围[-1,1]。

原保护M1为N+N对O+O；M2为N+H对O+H，H沿用已冻结原身份；J沿用未入训练的高级启发式并报告。M1最少128独立块、点估计≥55%且97.5%双侧块区间下界>50%；M2最少256块、下界>45%。新周期可依据先导在开封前增加固定N，不能看完低分再增加。旧REVIEW5一次确认规则不回改，本周期新规则另账。

开发选择保留种子可靠性：S=0.5×M1胜率+0.5×M2胜率；候选相对U0的S≥+5pp、J≥U0-5pp，重大合作错误无新增；教师臂三对平均主开发B-A差>0且至少两对>0；合格教师臂run至少两个，才按开发S取较低中位run。同分按pair固定顺序。若对照臂更好可如实留研究候选，但不能作为“教学有效”发布证明。

一次正式确认只测一个锁定候选，最多三次跨轮确认，使用全新清单。主检验单侧alpha=0.05/3；固定N后一次计算20,000次块bootstrap下界，算法与seed锁定，报告经验区间的近似性质；并并列有界Hoeffding敏感性，不在看结果后改用较有利方法。主下界>0且点改善≥3pp；每搭档组单侧同alpha下界>-3pp；原M1/M2门及严重反例全过才晋级。

确认bootstrap也使用percentile与R type 7分位，三组共用同一次完整基础块重采样索引，保留组间协方差。主下界取alpha分位，原M1/M2双侧97.5%下界取0.0125分位；不能把百分数或单/双侧弄混。统计实现与原raw块随包交付。

这些门是全部必须成立的交并检验，不择一过门；0.05/3是对最多三次候选主张的名义错误率分配。不能由此把每个搭档组的区间宣称为联合同时覆盖95%。若要额外宣称每一组均显著提升，事前另做Holm/Bonferroni；不能事后挑一组。经验bootstrap不是有限样本精确保证，近边界结论并列敏感性且保留这一限制。

正式N由64块先导、预定delta=5pp与主检验power≈0.8估算，再以有界二项/配对模拟复核。合作块N_primary取主检验与三个非劣门所需最大值；N_M1和N_M2分别计算，至少128/256。统计功效目标5pp与产品最低点改善3pp不同；80%主检验功效也不是全部门联合通过80%。预登记模拟至少包括：三组均+5pp，以及三组+15/0/0pp；M1真率0.60、M2真率0.50。保留组间相关性或给保守场景，报告所有必要门联合通过率及其模拟误差。若真实M1只等于0.55，点估门通过概率约一半，不能加N承诺80%。预算按各任务N独立计场；不能支持保护门就记不足。stats-plan.json逐项写公式、方差、N、备择假设、计量单位、选择规则，禁止只写“bootstrap通过”。

所有计划块进入账，超时、未完场与失败单列。只允许修执行后继续同一块、同一候选、同一协议；在未完成前不查看累计胜率。无法补全则incomplete，并给候选未完成取败/对照取胜的最坏界，不能删除失败块后得pass。正式封存题由未见match/家族构建；构造回归60例全是开发，不做盲测。

严重合作错误封存集初始24例，来源与生成家族不能与训练/开发重叠；在候选冻结前只核清单和标注契约，不把候选跑分给调参。类别至少含无收益炸队友、必要接管被漏掉、残局资源错误、规则事实错误。标签必须是规则/可解残局证明或合格信息集证据；证据不足不预贴唯一正确动作。候选与旧包同场一次打开，任何新增已证严重错误阻断发布；若合格标注少于24，记该门覆盖不足，不能拿60开发例补成封存。24是工程反例门，不作为罕见错误率的精确统计保证。

恢复仅适用于不改变语义的执行中断。若确认中发现规则、候选、策略、目标或统计语义需改，原attempt记invalid并占用一次已开确认额度，旧块保留但不得混入修后结果；新版本需要新封存清单和新的可用attempt。不能通过称“修执行”继续复用旧块与旧额度。

B对O的正式确认只支持候选升级。教学的因果增益在本周期仅有三个B-A开发对照提供初步证据，不称独立方法确认。后续若要更强因果主张，单独预登记新训练种子重复与封存B-A比较，另算预算和多重性。

新候选只能生成完整candidate bundle；不自动替换网页默认部署。确认过门后送出候选身份、门结果、风险和具体发布命令供审阅。已有明确发布授权时按授权执行；否则停在已完成的可审阅候选，不让用户为一份空计划批准。
