01 复查任务和最重要的结论

本资料由执行者 Codex 整理，提交给项目所有者及其委托的 ChatGPT 复查。范围包括用户提供的 REVIEW6.1 掼蛋 AI 执行方案在本机的实施、随后完成的 GitHub 首次上传，以及尚未完成的能力目标。目的在于让无法访问本机的审查者看见关键原件、真实数字、失败历史、代码和成本假设，并对停止决定及下一步优化提出独立意见。

截至本轮交付，整体目标没有达到。四席复盘的有限事实验收通过；数据做过审计；教师产生了四条合格先导偏好；两组各完成二十次真实的小规模学习更新。正式训练、独立技能考试、严重案例完整判定和正式比赛确认没有完成，网页仍用旧出牌政策，没有已验收的新候选。

执行者按原文的训练前成本规则停止当前已验证配方。最低档的已知后续工作加原定 25% 余量，修正后预计 145.676551 资源小时；计算时原账实际剩 56.118762 小时，最终结账剩 55.640472 小时。这个结果是有限先导外推，不能当作任何其他实现或硬件均不可能完成的证明，也不能把工程工作尚未实现与预算预测混为一谈。

请重点复查三件事：第一，已完成的工程和实验是否真实满足各自合同，而不是只看自报通过；第二，成本核算、样本量算法、有限先导的产出率及停止理由是否充分；第三，怎样在不改最终目标、不降低门槛、不复用已开封考试题的条件下，提高可靠教学和正式验证的效率。

07 四席复盘到底修复了什么

复盘链把规则事实、实际动作和旧政策偏好分开。修复重点包括：行动者与观察席位不同的时候仍正确显示；牌型和实际张数按记录确认；不能从某家 pass 推断其必定压不动；四炸五炸都能压住目标时，只能先陈述合法性，不能把启发式偏好写成规则；不同讲解出口、旧缓存和流式输出不能绕开事实校验。

验收使用预先固定的 60 个开放开发案例，每个案例在四个观察席位展示，共 240 张卡。每张卡至少覆盖目标牌与控制席、行动者和观察者、动作张数及身份、行动后余牌、规则比较和建议来源六类断言，总计 1440 项。最终已核 1440，缺失 0，错误 0；另做 717 个正常 UI 根身份的确定性核对。

真实浏览器收据 browser-acceptance-004 验证了四席页面。最终 HTTP 读回页面、事实面板源标识和后端 /api/health 均成功，实际 HTTP 获取的 clean2.f32 为 659460 字节且 hash 与原网页政策一致。此只证明当时服务版本，不能把 localhost 链接当作远程公开站点。

09 人类打法参考模型为什么未通过

H 是本地行为参考模型，用来模拟登记的人类行为分布，不是人类水平认证。按一次性合同固定抽取训练 6000、开发 8000、保留 8000 个决策；训练只做一次三轮，batch 32，564 个优化步骤，训练曝光 18000。H 的训练学习率是 0.0001，主团队学习的学习率是 0.001，不能混用。

其整体保留集 NLL 比均匀和频率基线更好，但原合同要求分层也达标。NLL 是对实际动作集合分配概率的负对数损失，越低越好；它不是胜率。保留集 pass 分层比同支持集频率基线差 0.186068，超过允许的 0.1，故质量门失败。

10 旧政策基线与搭档池的含义

旧完整政策开发基线实际运行 128 场完整 match，M1 和 M2 各 64 场、32 个配对块，同时输出 60 个开放根的旧 NN 偏好。M1 与 M2 都为 0.5 是同政策角色互补的自对照对齐结果，不是新旧对战的强度增益，也不能用来描述当前 AI 相对真人胜率。60 个开放根的策略 supported 仍为未知。

no_h 登记池包含干净 U0、旧完整政策、冻结 heuristic0 与 heuristic1，并固定使用三对旧 R5 政策中的 control 作为开发搭档、treatment 作为确认搭档。不同权重不等于人类，也不保证统计来源完全独立。登记表明确共享旧研究数据谱系，因此这些池的结果只能解释为所测非真人搭档范围。

教师续打使用两套固定四席配置。首手动作和后续政策身份都需锁定；不能把一套政策结果良好就临时挑它当教师。先导方差用 U0 和冻结 heuristic0 作为行为确实不同的探针，不使用这组的实际优势当作最终候选的预期收益。

三组合作主指标比较候选 N 与旧 O 各自搭同一留出搭档，对手固定为旧政策池，换边与发牌配对。M1 为 N 加 N 对 O 加 O；M2 为 N 加固定 H 对 O 加固定 H，此处 no_h 先导的 H 是登记的 legacy heuristic level1，不是未合格的人类参考模型。J 沿用未入训练的高级启发式检查，尚未测。

原开发入围规则还要求 S=0.5×M1胜率+0.5×M2胜率；相对U0的S至少增加5个百分点，J不低于U0减5个百分点，重大合作错误无新增。教师臂三对主开发B减A差的平均严格大于0、至少两对大于0，合格教师臂run至少两个，再按开发S取较低中位run，同分按pair固定次序。对照臂更好可以如实保留研究候选，但不能当作教学有效发布。这些正式选择均未运行。

11 新技能与严重案例做到哪里

技能来源草案按四类预锁最多 300 个候选来源，每类最多 75，目标每类取得 15 个合格家族，合计 60 家族、75 决策。它尚未产生生产标签。构题与答案验证应独立于候选模型的表现，不能按候选做对与否筛题。

原 24 个严重案例的完整可恢复实体和一一谱系映射未恢复。另准备了 96 个新来源的有界草案，四类各最多 24，计划每类取前 6 个合格家族。这个新队列不等于已找回原 24，也没有资格直接冒充原案例通过。原合同是否允许另建同要求新集，或者必须先补回缺件，仍需要复查明确；当前没有封存和验收，不存在已通过的替代集。

若能合法把严重例映射为技能集子集，必须是 24 个不同家族，并报告实际决策数；含条件对时决策数可能大于 24。若独立并列，也须报告实际交集，不能把 60 加 24 说成 84 个独立案例。零个已证错误但大量动作无法判断，不满足全部严重案例可判的能力门。

尚未实现的生产路径包括构题生成器、同目标验证器、plan labels seal 的完整执行和 capability.lock，以及与 candidate.lock、正式 opened 账的端到端连接。队列草案、schema 或算术小工具存在，不能算生产技能考试已实现。材料包刻意没有提供未来正式题的种子和内容，以免复查讨论使它们变成开发题。

12 教师目标与合法信息边界

每条教学结论比较的是完整比赛团队目标，而不是看下一手好看、单副提前结束、网络评分或启发式偏好。g 是决策所在副对该行动者队伍的带符号升级分，取负 3、负 2、负 1、1、2、3；W 是最终完整 match 的队伍胜负，取负 1 或 1。

y = g + W

训练A/B是两组学习臂；本节教师统计中的动作A/B是同一关键局面的两个动作分支，二者不是同一种身份。

因此 y 的范围为负 4 至 4。用于教师配对统计时采用归一化差值：

d = (y_A − y_B) / 8

教师主下界 0.02 的单位是这个归一化团队目标差，不是 2 个百分点的比赛胜率。学习目标仍用原尺度 y；显示用 z 不作为训练或强标签目标。训练样本必须等完整 match 结束后再把各决策对应的本副 g 与最终 W 合并，不能给整场所有动作同一个最后一副的 g。

教师输入只能读取自己的手牌和公开信息。条件信息集采样应在与公开历史、合法动作、进贡还贡等约束一致的物理世界中均匀抽样，不使用原始隐藏手牌来挑有利世界。两套不同合法隐藏世界下，观察、候选、输入、全部 Q 分和最终动作需一致，才说明网络没有直接读到暗牌；这仍不等于完整教师目标已通过。

执行层使用完整 108 张物理牌、公开历史和 indexed-deal-v1 的未来发牌。原生根信息必须一致；未来同源发牌谱系也需审计，不能只检查第一副 seed。超时、不完整 match 或规则问题保留并拒收，不按失败局计成输，也不抽一个有利替换世界补分母。

证据 match-play.ts；training-samples.ts makeMatureTarget；visible-world.ts；action-effect.ts；paired_stats.py。

13 受限多步计划及实际限制

计划是结构化 DSL，不允许任意 LLM 代码。最多控制本人的四次动作，不能替其他三席下指令。每步只可依赖已公开事实或自己的合法动作集合；计划不适用、触发不满足、失效、动作不存在或本副结束时回落到冻结续打政策。

当前 DSL 包含 goal、condition、trigger、invalidateWhen、fallback、maxOwnActions、steps。允许 eq lt le and or not 和合法牌型判断，递归深度上限 8、总节点上限 256、and/or 每层最多 8 项。可读事实包括 myTurn、myCount、partnerCount、opponentMinCount、partnerFinished、opponentFinishedCount、mateControls、hasTarget、targetKind、targetSize、targetKeyRank、myTeamLevel、opponentTeamLevel、myTeamOnStage、partnerLastPass。

注意：代码包含十五个 fact 字段；原文“十二条件计划”的具体映射和实现边界应逐项复查，不能仅因数量相近就算语义一致。事实来自可见状态，不允许 current hidden hands、未来发牌或来源隐藏布局字段。动作选择有 pass、finish_hand、exact_action、minimum_key，全部仍受真实合法候选约束。

每根分开报告四种比较：主续打下仅改第一手的 A 对 B；固定第一手后 Plan 对 A 的后段贡献；完整 Plan 对 Original；另一套四席续打下根动作 A 对 B 的敏感性。后段和整计划好，不代表第一手自身好。当前十八根全部不具备 plan-only-tail 收入资格，也没有 learnedPlanClaim。

已发现确定性公开信息表示缺口：两种合法的公开进贡情形可得到同一 331 维模型状态，而条件合法世界支持不同。该机械证据没有证明最优动作或完整比赛价值必然不同。相应根被排除于主 MLP 强标签；未启动 GRU 或声称记忆网络有收益。下一步先应验证这个信息差是否影响决策，再判断公开事实编码修复与学习记忆的必要性。

证据 plan-dsl.ts；teacher-engine.ts；memory-gap-001；review6_visible_world.test.ts。

18 二十次真实成熟更新的实现

A 和 B 从同一隔离的干净 U0 开始，均为 399→256→256→1、小网络 tanh、线性 Q，epsilon 0.05。A 使用团队损失和锚定，B 在同一规则上额外使用教师偏好。RMSprop 学习率 0.001，alpha 0.9，eps 0.00001，momentum 0，centered false，weight decay 0；每次只做一次合并 step。

L_A = L_team + 0.01 L_anchor

L_B = L_team + 0.01 L_anchor + 0.1 L_pref

L_pref = mean_root mean_pair softplus(0.16 − (Q_plus − Q_minus))

团队项为原 y 上的 MSE；锚定项对固定训练根每根候选先平均，再跨根平均，不能让候选多的局面权重大。偏好先在每根内部平均，再跨根平均，温度为 1。0.16 是原 y 尺度上的分差参数，不是 16% 胜率；softplus 超过 margin 仍有梯度。

no_h 的成熟 FIFO 容量按原合同分三桶。每次消费 2048 槽，配比 1024 self、512 frozen_opponent、512 other_partner；每桶不放回取一半形成梯度 512、256、256，共 1024。没有满桶就等，不从其他桶借，也不学冻结席位的动作；当前政策对应 4、2、1 个可学习席位。

实际完成 181 个源 match，含一个锚定 match、A 的 92 个和 B 的 88 个；A/B 同源配对流导致只有 97 个初始家族，不能把 181 说成 181 个独立来源。实际 round 引用 1784、去重物理发牌家族 1069，排除了既往 5855 个祖先键。共 46 波来源采集。

20 实际成熟速度与资源保护

A 成熟更新设备中位 1.205502 秒、P90 2.814174 秒；B 中位 1.211216、P90 2.916204 秒。Python 实际一步 P90 分别 0.024638 与 0.026990 秒。A 累计更新设备时间 29.745906 秒，B 为 28.581060。整个被管理执行窗 63.076 秒，保守按最大六份容量计费为 378.456 资源秒。

正式 B 每更新最多 64 个不同教师根，而本次只有 4 个。成本表没有伪造 64 个标签测速，而是把测得整个 B Python 一步成本乘十六的附加十五份计入，额外约 0.404849 秒/更新。这是保守外推，不是测到了 64 根的实际速度，也不是精确的教师项边际成本。

运行安全不是只在聊天里约定。实际保护包括：原预算 hash 链及唯一 lease 核对；不可变可执行快照；依赖路径及 hash；Python 在导入 Torch 前检查 stdlib 身份链；Node opened 记录与实际 PID；既有 Torch 六个关键文件共 240841380 字节的 hash 锁；绝对截止时间、TERM 后 KILL、整进程组清理，并等待组消失再结算。

主控制器自己死亡时，单靠它的 interval 无法收掉孩子。最终版本增加同一 owned PGID 内独立 watchdog，监测父死亡和单调时钟到期，必要时杀掉整个组及自身。最大六容量和 7200 秒预留在原周期内，soft 960、hard 1080 秒，1080×6+120=6600 小于预留；实际提前完成后按 378.456 结算。

Node、watchdog 与 Python 退出以及 lease 关闭均有实际收据。这里的最大六容量不是精确 CPU 使用秒；Torch 自身有两个线程，进程、线程、设备墙钟和保守资源账是不同量。应复查计费口径是否与原合同一致、是否有过度保守或重复计费，不能仅把进程数多当作硬件加速收益。

成熟试验 stderr 为 918374625 字节，约 918 MB，已保留在完整本机恢复点但没有放入精简材料包。未为本报告重新剖析其增长原因。可以优先检查 NODE_DEBUG、数据 URL 入口或重复模块日志，减少纯 I/O；这只是待验证优化假设，不能直接承诺足够弥补预算缺口。

附录 D 术语的通俗解释

术语 | 含义和常见误读
--- | ---
match | 从当前级别到整场最终赢家的一场完整比赛 可含多副牌
round 或一副 | 一次发牌后的局 不是训练轮次或完整比赛
root 或根 | 一个需要判断怎么出的具体关键局面 不是一次世界模拟
world 或信息世界 | 符合当时公开信息的一种合法未知牌分布 不是真实隐藏牌的泄露
来源家族 | 可能相互派生或共享最初发牌的来源簇 同家族不冒充新独立样本
supported | 在规定目标 信息和置信合同下有支持 不是全局最优或普遍正确
pilot | 有界小规模试验 用来测可行性 不能冒充正式训练或盲测
mature update | 完整比赛结果可回填 配额与半采样满足之后的一次真实参数更新
梯度 | 损失对参数的改变方向 非零只表示教学参与计算 不等于胜率增长
Q 分差 | 网络对两个动作的评分差 不是概率差 也不是完整候选首选率
P90 | 样本耗时的较慢分位 不是最快一次 也不是未来绝对上界
资源小时 | 原账按合同计的累计执行量 包括保守容量和工程上界 不等于CPU小时或美元
attempt opened | 正式考试第一次启动前原子登记的使用次数 不等于一次程序错误重试
冻结快照 | 实际执行用的只读代码 依赖 政策和种子身份集合 不是一张自报hash表
no_h | 不把未合格的人类参考模型加入搭档池 不能声称真人兼容
not implemented | 代码能力尚未写完 与运行后未达标不同
not run not measured | 未执行未测 应填未知 不能填0或100%
